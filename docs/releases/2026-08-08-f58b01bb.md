## 这次真正改善了什么

这次发布包含一批此前已经完成、但还未进入生产的阅读与探讨功能。以下只写用户会实际遇到的变化。自动化、文档和内部知识记录没有混进“新功能”。

### 长期阅读记忆终于能由用户自己掌控

**存在的问题**

探讨历史会按上下文分开保存，也会在送入模型前裁剪或压缩。稳定的偏好、观点、目标和待办若只留在旧聊天里，过一段时间便难以继续沿用，用户也没有地方查看或纠正。

**实现方法**

“我的”抽屉新增“阅读长期记忆”。用户可以把偏好、观点、目标或待办明确保存，也可以编辑和删除。系统只保留用户确认的内容。探讨时会带入全局记忆，以及与当前书籍或摘抄相关的记忆，最多八条。

**最终效果**

例如“希望先从具体段落讨论”这类习惯不必反复说明，同时每一条被保存的信息都可见、可改、可删。旧账号缺少该字段时会以空列表兼容加载。

### 删除探讨记录失败时，界面不再假装删除成功

**存在的问题**

网络或服务端删除请求失败时，原来的页面仍会清空聊天气泡。用户以为记录已删，刷新或重新进入后却发现历史又出现，既无法判断数据是否真的删除，也失去了当场重试的上下文。

**实现方法**

只有服务端确认删除成功后，聊天页才清空本地历史。请求失败会显示错误，并保留当前对话。

**最终效果**

删除失败时，历史仍留在眼前，用户可以直接重试。数据与界面保持一致，不会再出现“删了又回来”。

### 摘抄探讨会继续回到正确的摘抄

**存在的问题**

早期保存的摘抄级探讨，在缺少完整上下文信息时可能被错误归入整本书。用户从一条摘抄进入对话时，可能看不到原本属于它的历史。

**实现方法**

历史键和上下文迁移逻辑会识别摘抄范围，即使旧数据只保留摘抄标识，也不会降级成书籍范围。

**最终效果**

从摘抄进入探讨时，原有对话能被恢复到对应摘抄，不会和整本书的讨论混在一起。

### 书单卡片更容易扫读，标签筛选也不再挤成一排

**存在的问题**

书单卡片同时堆叠评分、标签、阅读次数、分钟数、页数、关联数等信息。手机上快速浏览时重点不突出。标签稍多后，筛选条也会占满横向空间，难以找到想要的主题。

**实现方法**

书单卡片保留作者、阅读进度和摘抄数，把评分与完整标签放到书籍详情。标签筛选默认展示覆盖书籍最多的三个，并提供“更多标签”入口，可搜索全部标签并显示每个标签关联的书籍数。

**最终效果**

书单更适合快速判断读到哪里、有没有摘抄。需要按主题找书时，也不必在一长串横向标签里反复滑动。

### 书籍详情补上最近阅读轨迹和删除影响

**存在的问题**

打开书籍详情后，用户无法快速知道最近读了几次、读到哪些页。删除一本书前，也不知道会连带删掉多少记录、摘抄和关联。

**实现方法**

详情页显示最近五条阅读记录、累计次数和时长，并可跳转查看全部记录。删除确认框会提前列出将被一并删除的阅读记录、摘抄或笔记，以及关联数量。

**最终效果**

回顾一本书的阅读过程更直接。删除前的影响可见，用户能在确认前判断是否需要保留数据。

### 关联操作不会重复制造同一条想法连接

**存在的问题**

同一对内容重复提交关联想法时，过去可能生成重复连接，后续回顾会出现重复卡片。

**实现方法**

服务端在执行关联操作前检查已有的同向连接，并对重复请求保持幂等。

**最终效果**

重复点击或重试不会重复写入同一条连接，已有的反向连接仍会保留为独立关系。

## 维护与发布保障

- 模型配置可通过环境变量指定，部署时不再依赖固定模型名。
- 夜间选题、实现和探索流程迁至 Codex Cloud 调度，开发分支仍是 `feature/agent`，生产发布仍由统一脚本执行。
- 本次范围的 Python 回归测试和前端测试均已通过。发布后本地生产入口与公网入口均返回 HTTP 200。

## 数据与兼容性

长期记忆以 `memories` 字段存入现有用户状态。旧数据不会被改写或删除，未包含该字段的账号会正常加载。此次发布脚本未执行生产数据库迁移，也未删除用户上传文件。

## 回滚信息

若需要回滚，可将生产代码切回上一生产版本 `c58981b` 后重启服务。发布脚本不会自动删除数据库内容或用户上传文件。
